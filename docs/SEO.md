# קידום האתר בגוגל — בדיקה ותוכנית המשך

תאריך הבדיקה: 17.09.2026. הדומיין שאושר: https://www.nofarkapury.co.il/

## שיפורים שבוצעו בקוד

- בניית HTML סטטי מלא מתוך React: התוכן, הכותרות, התמונות והקישורים קיימים לפני JavaScript. לאחר מכן React מפעיל את הרכיבים האינטראקטיביים באמצעות hydration.
- כותרת ותיאור בעברית שמסבירים את השירות והמיקום: איפור ועיצוב שיער לכלות באשדוד ובכל הארץ.
- כותרת H1 אחת, עם תיאור שירות גלוי לצד כותרת המותג; תוכן השירותים ופגישת ההיכרות תואם לפרטים שסיפקה בעלת העסק.
- כתובת canonical אחידה בדומיין שאושר, תגיות Open Graph ותמונת שיתוף מקומית.
- robots.txt ומפת sitemap.xml נוצרים בכל build. המפה כוללת את עמוד הבית, מדיניות הפרטיות והצהרת הנגישות; מקטעים אינם עמודים נפרדים.
- JSON-LD מסוג Organization, WebSite, WebPage ו־Service, כולל טלפון, אזור שירות, אינסטגרם ופרופיל Maps שאושר. לא נוספו דירוגים, מחירים, שעות פעילות או כתובת לקבלת קהל שלא אומתו.
- לא סומן LocalBusiness לצורך תוצאה עשירה: טרם הובהר אם הכתובת הציבורית במפות היא מקום לקבלת קהל, ופגישות ההיכרות נערכות בבית קפה. אין להציג כתובת בית קפה ככתובת העסק.
- גרסאות WebP לתמונות הגלריה; תמונת הפתיחה זמינה ברוחב 640, 960 ו־1280 פיקסלים עם srcset. גרסת 1280 ירדה מ־1,368,590 ל־121,194 בתים — כ־91% פחות. המקור נשמר.
- טעינת תמונת הפתיחה בעדיפות גבוהה, טעינה עצלה לגלריה, מידות תמונה מפורשות וגופנים מקומיים.
- מסמך 404 בעברית. שרת התצוגה מוגדר לא להחזיר את עמוד הבית עבור כתובות לא קיימות.

## בנייה ובדיקות

בדיקות גרסת הייצור עברו: build, ESLint, שלוש בדיקות SEO ושש בדיקות דפדפן במחשב ובנייד, כולל תוכן ללא JavaScript, אינטראקציות ובדיקות נגישות אוטומטיות.

במדידת Lighthouse מקומית במצב נייד, ללא בדיקות דפדפן מקבילות, התקבלו: SEO ‏100, ביצועים 98, נגישות 100 ו־Best Practices ‏100. ‏LCP: ‏2.4 שניות; CLS: ‏0.001; TBT: ‏40 מילישניות. הדוח נמצא ב־`artifacts/lighthouse.html`. המדידה תלויה בסביבה; הרצה במקביל לבדיקות דפדפן נתנה ביצועים 79. אלה נתוני מעבדה, לא נתוני משתמשות אמיתיות, אישור עמידה בתקן נגישות או הבטחת דירוג בגוגל.

```powershell
.\npm-local.cmd run build
.\npm-local.cmd run test:seo
.\npm-local.cmd run test:e2e:production
.\npm-local.cmd run lint
```

`npm run build` מייצר את האתר הסופי בתוך `dist/`. רק תיקייה זו מועברת לאחסון; `.prerender/` היא תיקיית ביניים, ולא שרת שיש לפרסם.
כלי הפיתוח `npm run dev` נשאר במצב noindex. יש לבדוק SEO מול build/preview, לא מול שרת הפיתוח.
ברירת המחדל של build היא אתר ייצור הניתן לאינדוקס בדומיין שאושר. עבור staging יש להגדיר `SITE_INDEXABLE=false` במשתני סביבת הבנייה; מצב זה אינו מפרסם מפת אתר ואינו חוסם סריקה, כדי שמנוע החיפוש יוכל לקרוא noindex.
אפשר לשנות דומיין באמצעות `SITE_URL`. מתקבל רק origin ציבורי ב־HTTPS ללא נתיב, query או כתובת מקומית.

## ממצאים מחוץ לקוד

1. **הדומיין:** נמצאו אזכורים היסטוריים וקישור מהעסק במפות. עם זאת, ניסיון גישה ישיר מהמחשב החזיר `ENOTFOUND`/`ERR_NAME_NOT_RESOLVED`. לא התאפשר לבדוק אתר חי, מפת אתר ישנה, הפניות או אינדוקס נוכחי. זו תוצאת הבדיקה בסביבה זו, ולא הוכחה עצמאית לתקלה גלובלית. יש לאמת DNS ואחסון אצל ספק הדומיין לפני העלייה לאוויר.
2. **מפות:** המשתמש אישר את הרישום „נופר קפורי - איפור שיער לכלות וערב” בהצוללים 5, שלו 12 ביקורות בזמן הבדיקה. קישור מדויק: https://www.google.com/maps?cid=18267426247887072473 . לא הועתק דירוג לאתר.
3. **רישום נוסף:** אותר „נופר קפורי” בהציונות עם אותו טלפון וללא ביקורות. כדאי לבדוק דרך ניהול הפרופיל/תמיכת Google אם מדובר בכפילות או בכתובת ישנה. לא בוצעה מחיקה, מיזוג או עריכת פרופיל.
4. **עקביות פרטים:** נמצאה באינדקס איזי כתובת ישנה בהציונות. כדאי ליישר פרטי עסק ופרטי התקשרות בין האתרים בהתאם למצב בפועל, בלי להוסיף שם עסק או קטגוריות שאינם מייצגים אותו.

## מה נדרש בהשקה

1. לחבר את הדומיין לאחסון ולהפעיל HTTPS תקין. להפנות ב־301 את HTTP ואת הגרסה ללא www אל `https://www.nofarkapury.co.il/`, תוך שימור נתיבים ופרמטרים.
2. להגיש את `dist/` כאחסון סטטי. אין להגדיר הפניית SPA גורפת של כל הכתובות לעמוד הבית בסטטוס 200. כתובות לא קיימות צריכות להחזיר 404 אמיתי עם `404.html`.
3. אם היה אתר קודם, לייצא את הכתובות מתוך Search Console/האחסון/מפת האתר הקודמת. לשמר עמודים מועילים או להפנות ב־301 לעמוד חלופי רלוונטי. אין עדיין מיפוי הפניות מאומת.
4. לאמת בעלות על נכס הדומיין ב־Google Search Console דרך DNS, לשלוח `https://www.nofarkapury.co.il/sitemap.xml` ולבדוק את עמוד הבית באמצעות URL Inspection. לא נוספה תגית אימות פיקטיבית ולא נשלחה בקשת אינדוקס מתוך סביבת העבודה.
5. לבדוק שעמוד הבית מחזיר 200, robots מאפשר סריקה, אין noindex בייצור, canonical נכון, נתוני JSON-LD תקינים ב־Rich Results Test ו־Schema Markup Validator, ותמונות/גופנים נגישים.
6. לבדוק PageSpeed Insights בכתובת הציבורית ולעקוב אחר נתוני Core Web Vitals אמיתיים כשהם זמינים. מדידה מקומית אינה מייצגת את מהירות האחסון או את כלל המבקרות.

## עבודה שוטפת לשיפור נראות מקומית

- לשמור על פרופיל העסק מאומת ומעודכן: שירותים אמיתיים, אזור שירות, טלפון, אתר, תמונות ושעות מענה נכונות. השם צריך להיות שם העסק האמיתי, ללא הוספת מילות מפתח מלאכותית.
- לבקש מלקוחות אמיתיות חוות דעת כנות ולהשיב להן. אין לקנות ביקורות, לתת תמורה בעבורן או לסנן רק לקוחות מרוצות.
- להוסיף עבודות חדשות ומידע מקורי שעוזר לכלות לבחור: איך מתנהלת פגישת ההיכרות, הכנה לבוקר החתונה, בחירת תסרוקת וסיפורי כלות בהסכמתן. רק תוכן שמשקף את העבודה בפועל.
- בהמשך אפשר לבנות עמודים נפרדים לשירותים כאשר יש לכל אחד תוכן מקורי ומועיל. אין טעם ליצור עמודים כמעט זהים לכל עיר או להעמיס מילות מפתח בעמוד הבית.
- לדאוג לקישורים רלוונטיים ממקומות שבהם העסק באמת מופיע: Instagram, Google Business Profile, אינדקסי חתונות ושיתופי פעולה אמיתיים.
- לעקוב ב־Search Console אחר חשיפות, הקלקות, חיפושים ועמודים; להשוות לאורך שבועות וחודשים. המטרה העסקית היא פניות מתאימות, ולא ציון בדיקה בפני עצמו.
